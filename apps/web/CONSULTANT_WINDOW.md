# Окно КонсультантПлюс

Текст ФОП для динамических разделов загружается при сборке из `consultant.ru` через `apps/web/frp-noo-content.js`. Разрешённое окно источника: будни 20:00–24:00 МСК (00:00–04:00 по Сайгону); выходные — весь день.

## Scheduled source-check

Workflow: [Web CI](../.github/workflows/web-ci.yml), cron `30 17 * * 1-5` UTC (20:30 МСК / 00:30 по Сайгону). Ожидаемое число динамически извлечённых разделов — **125 из 125**.

Проверка источника считается VERIFIED только при выполнении всех условий:
- запуск имеет событие `schedule` и выполняется внутри окна;
- лог показывает `[noo-content] программ: 125 из 125`;
- список ошибок пуст, нет предупреждения о резервном корпусе;
- в итоговой аннотации присутствует `n=125/125`.

Успешная сборка по событиям `push` или `pull_request` сама по себе не доказывает доступность источника: вне окна или при временной блокировке сборка может использовать встроенный корпус ЕДСОО. Такой fallback сохраняет работоспособность приложения, но не является проверкой живого текста ФОП.

Если scheduled-run извлёк меньше 125 разделов, фиксировать точное число и каждую причину ошибки из лога; проверка должна считаться неуспешной. Не переписывать учебные материалы автоматически и не повышать их статус актуальности на основании fallback.
