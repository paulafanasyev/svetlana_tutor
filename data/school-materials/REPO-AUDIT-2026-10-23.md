## Конкретно по отклонённому push

В предоставленном логе GitHub Actions коммит бота `51cc31e` был создан локально, но отправка завершилась `[rejected] ... (fetch first)`: удалённая ветка уже содержала другой коммит. Это race/non-fast-forward, а не ошибка тестов или генерации индексов.

В актуальной версии `.github/workflows/school-materials-sync.yml` добавлена безопасная последовательность `git fetch` → `git rebase origin/<branch>` → `git push` с тремя попытками. Она не использует `force-push`. Последующий успешный run #39779169138 подтверждает, что новый путь синхронизации завершился полностью. Исторический failed run не следует перезапускать как проверку нового кода: rerun старого события не является доказательством работы текущего workflow.

Если будущая синхронизация упадёт при rebase из-за конфликта одного и того же файла, это должно остаться явной ошибкой для ручного согласования — не решать конфликт автоматической перезаписью данных.
