## Практические правила до серверной версии

1. Использовать инициалы или обезличенные коды; не записывать диагнозы, адреса, телефоны, семейные обстоятельства и другие подробности, не нужные для учебной задачи.
2. Не сохранять документы с данными учащихся в общедоступном или совместно используемом браузерном профиле.
3. Считать скачанный JSON резервной копией с открытым текстом. Хранить его в доступном только уполномоченному пользователю защищённом месте; перед отправкой/публикацией проверить файл на персональные данные.
4. При прекращении использования удалить локальные черновики, историю чата, загруженные архивы и другие копии отдельно. Очистка localStorage сама по себе не удаляет скачанный JSON и копии вне браузера.
5. Не направлять настоящий файл учащегося в ИИ для проверки без разрешённого процесса, минимизации данных и необходимых организационных оснований.

## План инженерного усиления

- [ ] Серверная аутентификация и авторизация, роли пользователя/учителя/администратора, изоляция по школе/организации; запрет полагаться только на user ID на клиенте.
- [ ] TLS для передачи данных, шифрование хранения и резервных копий на стороне сервера, управление ключами и их ротация.
- [ ] Минимизация собираемых данных и явное описание назначения каждого поля.
- [ ] Политика хранения/удаления, возможность экспорта и удаления данных с учётом всех резервных копий и сроков их ротации.
- [ ] Журнал доступа и изменений без записи содержимого детских документов в технические логи.
- [ ] Автоматические резервные копии и регулярные тесты восстановления с доказательством, что копии доступны только разрешённым лицам.
- [ ] Проверки на межпользовательский доступ, обработку XSS, небезопасные загрузки, утечки секретов и неправомерное включение документов в телеметрию/ошибки.
- [ ] Проверка правового основания обработки, текста уведомления/согласий, локальных актов, ролей оператора и обязательных процедур с профильным юристом и ответственным за персональные данные до пилота с реальными данными.

## Граница статуса

**VERIFIED** описывает лишь видимые в исходном коде свойства текущего приложения. **NOT PROVEN** означает, что безопасность или юридическое соответствие не были доказаны испытанием. **PENDING** требует реализации, тестов и/или проверки ответственными специалистами. Этот документ не подменяет технический аудит развёрнутой среды, оценку угроз или юридическое заключение.
