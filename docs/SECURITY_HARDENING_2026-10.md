# Усиление безопасности, октябрь 2026

Дополняет `SECURITY_AUDIT.md` (июль 2026).

## Сайт (Vercel, `vercel.json`)

| Защита | Что даёт |
|---|---|
| Content-Security-Policy | Скрипты только с сайта, esm.run/jsDelivr (WebLLM, onnx, Piper) и GTM. Встроенные `<script>` и `on*=` не выполняются, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`. |
| `frame-ancestors 'none'` + `X-Frame-Options: DENY` | Сайт нельзя встроить в чужую страницу (кликджекинг). |
| HSTS 2 года | Только https, без даунгрейда в публичном Wi-Fi. |
| Permissions-Policy | Микрофон/камера только сайту и Jitsi; геолокация, оплата, USB, Bluetooth выключены. |
| nosniff, Referrer-Policy, COOP | Нет угадывания типов, адреса не утекают, окно изолировано. |
| `/.well-known/security.txt` | Куда сообщать об уязвимостях. |

Осознанные послабления: `'unsafe-eval'`/`'wasm-unsafe-eval'` (WebLLM/onnxruntime), `connect-src https:` (модели с нескольких CDN), `style-src 'unsafe-inline'` (React-стили).

## Сервер (`apps/api`)

- **Блокировка подбора пароля по аккаунту** (`src/lib/loginGuard.js`): 5 неверных паролей подряд за 15 минут закрывают вход в этот аккаунт на 15 минут с любого IP (ответ 429 + Retry-After). Закрывает остаточный риск A07.
- **Одинаковое время ответа** для несуществующего e-mail и неверного пароля (сравнение с фиктивным bcrypt-хэшем): по таймингу не узнать, какие аккаунты есть.
- **Обнаружение кражи refresh-токена**: повторно предъявленный уже использованный токен отзывает все сессии пользователя.
- **Лимит пароля 72 байта** (предел bcrypt), лимиты длины e-mail и токенов.
- Тесты: `tests/security.test.js`.

## Что не закрыто

- Опубликованная веб-версия хранит аккаунты, роли и монеты в браузере. Подмену через DevTools на устройстве не закрыть без сервера: нужен сервер (в РФ) с этим API.
- Блокировка подбора хранится в памяти процесса; при нескольких репликах API перенести в Redis.
- 2FA для админов нет.
