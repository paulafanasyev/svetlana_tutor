# Усиление безопасности, октябрь 2026

Дополняет `SECURITY_AUDIT.md` (июль 2026). Аудит 21.10 тремя критиками (код и взлом, дети и закон, релиз и CI).

## Сайт (Vercel, `vercel.json`)

| Защита | Что даёт |
|---|---|
| Content-Security-Policy | Скрипты только с сайта, esm.run/jsDelivr (WebLLM, onnx, Piper) и GTM. Встроенные `<script>` и `on*=` не выполняются, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`. |
| `frame-ancestors 'none'` + `X-Frame-Options: DENY` | Сайт нельзя встроить в чужую страницу (кликджекинг). |
| HSTS 2 года | Только https. |
| Permissions-Policy | Микрофон/камера только сайту и Jitsi; геолокация, оплата, USB, Bluetooth выключены. |
| nosniff, Referrer-Policy, COOP | Нет угадывания типов, адреса не утекают, окно изолировано. |
| `/.well-known/security.txt` | Куда сообщать об уязвимостях. |

Осознанные послабления: `'unsafe-eval'`/`'wasm-unsafe-eval'` (WebLLM/onnxruntime), `connect-src https:` (модели с нескольких CDN), `style-src 'unsafe-inline'` (React-стили).

## Сервер (`apps/api`)

- **Подбор пароля** (`src/lib/loginGuard.js`): 5 неверных паролей с одного адреса закрывают вход в этот аккаунт только для этого адреса на 15 минут; 50 ошибок со всех адресов (распределённая атака) закрывают аккаунт. Чужой человек, зная почту ребёнка, больше не может заблокировать ему вход.
- **Одинаковый ответ и время** для несуществующего e-mail и неверного пароля.
- **Кража refresh-токена** (`src/lib/refreshReuse.js`): старый токен, предъявленный позже 30 с после смены, отзывает все сессии; две вкладки, обновившие вход одновременно, не выкидывают пользователя.
- **Магазин** (`src/lib/catalog.js`): цену назначает сервер по каталогу, цена от клиента игнорируется, неизвестные товары — 404. Раньше любой товар можно было купить за 1 монету.
- Лимит пароля 72 байта (предел bcrypt), лимиты длины e-mail и токенов.
- Тесты: `tests/security.test.js`, `tests/economy.test.js`.

## Веб-приложение

- **Нет демо-администратора** в опубликованной сборке: вход admin@demo убран, роль ADMIN, вписанная вручную в localStorage, сбрасывается в STUDENT. Включается только локально или с `VITE_DEMO_ADMIN=1`. При работе с сервером (`VITE_API_URL`) демо-входы скрыты.
- **Цены магазина** из `src/data/shopCatalog.js`, а не из нажатой кнопки.
- **Детский фильтр** (`src/ai/childSafety.js`):
  - проверяет все поля заданий (phrase, vocab, answers, point и др.);
  - ловит обходы: «k.i.l.l», «k1ll», «у б и т ь», полноширинные буквы, невидимые символы;
  - ответ модели тоже проверяется: ссылки, телефоны, почты убираются, опасная инструкция заменяется отказом (`useAI.js`).
- **Чат класса** (`features/school/schoolStore.js`): сообщения и домашние задания учителя тоже проходят фильтр; телефон, почта, ссылки, @ник и адрес ученика скрываются до сохранения; имя видеокомнаты — 16 случайных символов (не угадать по коду класса).
- **Кадетская версия**: в выборе видно «10+», для младших наставник говорит мягко, без строевых слов.
- Тесты: `src/ai/childSafety.audit.test.js`, `src/features/school/schoolStore.test.js`, `src/data/shopCatalog.test.js`, `src/data/tracks.test.js`.

## Что не закрыто

- Опубликованная веб-версия хранит всё в браузере: данные на своём устройстве можно править через DevTools. Настоящая защита — сервер (в РФ) с этим API.
- Блокировки подбора и учёт токенов — в памяти процесса; при нескольких репликах API перенести в Redis.
- 2FA для админов, lock-файлы зависимостей, закрепление GitHub Actions по SHA.
- Юридическое: утверждённая политика, подтверждаемое согласие родителя, уведомление Роскомнадзора, свой Jitsi.
